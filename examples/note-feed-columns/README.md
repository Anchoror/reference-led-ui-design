# 公开笔记信息流：单列与双列连续对照

同样六条笔记、同样顺序、同样字体和信息字段，比较单列与双列怎样影响图像识别、内容密度与连续浏览。两侧都采用轻量信息流：封面、最多两行标题、作者与点赞；正文和话题进入详情阅读。

这是获准公开的独立 HTML 设计草稿，展示研究与比较方法；不代表已经选定双列、发布原生 App 或证明某种布局的业务效果。

## 运行可操作草稿

在仓库根目录运行：

```bash
python3 -m http.server 8789 --directory examples/note-feed-columns
```

打开 [本地对照页](http://127.0.0.1:8789/)。需要 Python 3，不需要安装前端依赖。单独查看可打开 [单列页面](screen.html?layout=single) 或 [双列页面](screen.html?layout=double)；GitHub文件页用于查看源码，交互需要通过本地HTTP服务运行。

可以独立滚动两侧；勾选“联动相同距离”比较相同像素滑动的内容覆盖，或定位同一条笔记。也可切换原尺寸和长标题样例。筛选、地区与点赞在两侧同步；点击笔记可进入、返回，保留浏览位置。

## 从反馈得到的判断

- 参考的质感来自字体实际占比、图文密度、图片内部构图及留白关系。直角和单列符合，只证明结构的一部分符合。
- 短中文页名与拉丁窄体的文字面积不同；已有字段替换成另一种信息后，需要重新组织排版，不能只复制字号与间距。
- 公开发现笔记和阅读文章承担不同任务。作者、话题与反馈应围绕当前判断组织，不能为了填满文字区自动补摘要。
- 比较列数时，两边应使用相同内容条件。连续查看中段与末尾，不能用首屏漂亮或内容更多直接证明更好。
- 完整竖图会增加高度，缩小图片会影响细节识别；需要同时展示收益与代价。比例、字级与列数都不是其他任务的固定模板。

通用规则已收敛到 [排版关系与浏览节奏](../../skills/reference-led-ui-design/references/layout-and-browsing.md)。

## 验证与边界

- 两侧默认六条内容、顺序、图片、字体逐项一致；图片加载、直角/透明模块、390与360宽度、长文本无横向溢出已检查。
- 独立滚动和相同像素联动、六条逐项定位、全部滚到末尾、分类空态/恢复、地区与点赞同步、详情返回、减少动态及途中反向已检查。
- 此样例390宽下的可滚动距离为单列约2256px、双列约418px。真实边界停止，不复制笔记或添加假空白；末尾定位可能无法顶对齐。
- 示例数据与交互在浏览器内运行；未接线上 API，未做原生构建、设备性能或业务 E2E 验收。更高密度不等于已经证实更高效率或转化率。
