# 案例来源与证据

## 候选入口

以下入口供研究时筛选。按当前任务选取，不要求每次访问全部；使用时核实可访问性、付费/登录限制及具体案例。网站名气不证明某个方案适合产品。

| 来源 | 值得寻找的内容 | 核查重点 |
| --- | --- | --- |
| [Design Spells](https://designspells.com/) | App 微交互、按钮、状态切换、页面过渡 | 看完整原片，避免只看封面；进一步找原产品或作者 |
| [Mobbin](https://mobbin.com/) | 移动端页面、真实产品流程与状态 | 静态截图不能证明动画；登录不可访问时如实说明 |
| Epub360 作品库、数英 Digitaling | H5 活动、叙事和互动项目 | 找实际作品入口，核对手机交互；策划包装图与作品分开 |
| [Codrops](https://tympanus.net/codrops/) | 页面转场、布局实验、可操作 demo | 实际操作；桌面鼠标效果需重新适配手机触控 |
| [HOVERSTAT.ES](https://www.hoverstat.es/) | 非常规布局、品牌表达与实验交互 | 不把桌面表现直接套入移动 App |
| [landing.love](https://www.landing.love/) | 站点展示、视觉节奏与动态编排 | 展示录像与实站操作分开；注意内容可读性 |
| [Awwwards](https://www.awwwards.com/) | 多样的视觉方向、作品与作者定位 | 进入具体作品，避免把获奖标签当适用理由 |
| [Bruno Simon](https://bruno-simon.com/) | 空间化界面、实体物件与交互关系 | 品牌体验是类比来源，不自动代表 App 操作效率 |

按任务补充 Behance/Dribbble 作者项目、品牌官网、原生产品演示等第一手资料。不要把候选名单当成已经学习过的案例。

## 一张案例记录应包含什么

根据任务取舍字段，不强制写成长报告：

```text
案例 / 作者 / 原地址：
类型：真实产品、设计概念、实验 demo、宣传展示等
实际观看范围：哪些页面、滚动区段、原片及长度、实际操作了什么
证据：静态观察 / 录屏完整分析 / 实站操作 / 作者说明 / 推断
风格：构图、字级比例、颜色面积、留白、材质；或动作层次
空间性（按案例相关性记录）：前后景、透视、体积、遮挡、光影及运动轴；哪些机制构成案例特点
优势与代价：具体帮助了什么，哪些场景不合适
角色：主参考 / 辅助参考 / 未采用
适配：当前页面哪个位置或动作借用什么，怎样改变，为什么
限制：未观看/未验证的部分，以及不能据此得出的结论
```

动效另附动作分组：段名、时间与帧范围、实际图组、各层动作与衔接、触发证据、移植方式。多个原片分别记录，避免混淆来源。

## 证据强度影响推荐范围

- 单张封面：可以讨论可见构图，不能称已研究整套产品。
- 多页静态图：可以讨论页面结构与状态差异，不能推断帧间运动。
- 完整录屏：可以分析所展示的动作，未出现的手势、返回和边界状态仍未知。
- 实际操作：可以描述自己操作得到的反馈；浏览器效果不等于原生性能或真机手感。
- 作者文字：可注明作者如何描述实现，不能替代自己的观看证据。

不能播放的候选可以保留为静态辅助来源，不应作为未经分析的核心动效依据。候选淘汰理由简要保留即可，不堆砌大量无效链接。

## 呈现方式

页面研究以真实界面图为主，说明放在旁边；动效以原片、动作分组和图组为主。提供可直接打开的地址。不要只列网站首页或大段抽象理论。

拍屏或裁切需保留理解所需上下文。组图中标记方向、帧号/时间，末页空格解释为排版占位。完整视频、全帧组图和采样概览分别标记；无法呈现的资源说明原因，给可核查原地址。
