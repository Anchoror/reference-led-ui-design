# 设计判断示例

这些示例说明如何读取参考、保留核心机制并适配产品。它们不是固定布局、技术方案或配色模板。

## 空间轮播：保留机制

[Codrops · 3D Gradient Carousel](https://tympanus.net/Tutorials/3DGradientCarousel/)可作为空间轮播的研究入口。实际使用前操作相关流程并记录观察范围，检查中心与两侧的Z位置、转角、尺度和遮挡如何连续变化。只留下横移或平面折叠，可能遗漏案例成立的主要机制。

适配移动端时，可让照片参与空间变化，标题与操作保持稳定；选中照片进入详情时接续到目标图片区域。是否采用这些处理，取决于当前页面和操作需求，不能直接套用。

## 体积云：分清表达方式

[Three.js 官方 Volume Cloud](https://threejs.org/examples/webgl_volume_cloud.html)可作为体积表达的研究入口。观察旋转过程中轮廓、密度、明暗和自遮挡的关系；不能把它简化成同心波纹或平面图层自转，却宣称实现了相同效果。

真实体积渲染、三维平面和二维视觉暗示各有成本与适用场景。根据所需效果选择，不能因为出现“空间性”就强行上WebGL；头像等身份信息是否跟随旋转，也需单独判断其可识别性。

## 跨页过渡：核对两端布局

头像进入个人主页，应先看入口位置、目标头像位置、封面、资料与内容区。共享物件接续、旧页退后、文字接力只是可选方法；不要替换成无关的欢迎页或引导浮层。

返回、侧滑取消与中途打断应和进入关系一致。若参考只展示进入，就把返回设计明确标为自己的适配，不能说成原作行为。

## 页面个性：避免只换表皮

同一色板、玻璃材质、大标题或等权卡片不足以构成完整方案。先确定主角、比例、前后景、色彩面积和操作关系，再用现有内容检验。认可的布局或局部可以保留，不必每轮全部重画。

从必要结构开始，允许有依据的复杂设计。英文小字、编号、装饰线和额外说明都应有可解释的职责，而不是惯性添加。

## 边界语言：不要研究完又套回模板

参考用直角照片、文字直接落底和留白建立层次时，圆角图片加圆角底卡会改变其主要视觉语法。应在开始画稿前记录这套边界关系，再把它对应到实际照片、标题、分组与操作控件。不能只保留图片题材，便宣称完成风格适配。

如果触控或既有控件契约要求局部圆角，明确指出适用对象及原因；这不能成为给整页内容加圆角容器的依据。最后并置原参考与草稿检查，区分直接借鉴、必要适配和自己的新增处理。

## 从编辑排版到发现流

需要进一步判断中文文字面积、图片预览职责、信息分组和单列/双列公平比较时，读取[排版关系与浏览节奏](layout-and-browsing.md)。参考的结构符合只是起点，最终密度与交互取决于当前使用任务。
