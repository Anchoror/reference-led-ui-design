# 参考驱动的页面与动效设计

目标：主动提出有依据、有特点的设计建议，让用户能看懂案例为何适合、哪些被借用、怎样适配当前产品，再通过草稿评估效果。默认用用户语言沟通。

## 先确定任务和实际基准

- 区分页面视觉重设计、单个控件、页面转场、开场动画。围绕用户具体动作工作；头像进入个人中心，不能做成欢迎页或新手引导。
- 先查看现有页面的实际图像、可操作页面或视频，再核对必要源码、布局和入口。记录起始页、目标页、组件位置、信息层级、现有素材和平台。源码用于核实结构，不能代替看画面。
- 用户未排除现有布局时，动效必须适配当前布局；页面重设计可以调整布局，但沿用已知内容、能力和导航语义。缺失关键页面时说明缺口，不自造通用页面替代现状。
- 用户提供的页面与自行找到的参考都要认真读取其空间性，不局限于首页。用户指定某页为主参考时，提取它的构图、空间关系、物件职责、文字比例、材质和用光；其他页面可各有构图，不能只统一配色，也不必复制同一物件。
- 只声称读取过实际可见的对话或证据。需要其他聊天时使用可用且获授权的历史工具；不假定已看到项目所有聊天。

## 跨站寻找，再认真学习

参考入口与记录格式见 [案例来源与证据](references/evidence-and-sources.md)，查找案例时读取。

1. 从用户任务提取匹配维度：要解决的观察/操作问题、空间关系或状态变化、风格、设备和手势。先匹配结构，再判断表面风格；不限于同行产品。
2. 从不同网站筛选有效候选，避免长期只用一个站。数量服从证据与差异，不为凑数加入弱案例。聚合站帮助定位，优先进一步查看作者、产品或可操作原站。
3. 静态页面仔细检查实际 App/H5 界面及上下文：版式、比例、字体层级、色彩面积、留白、边界、材质、主次、信息密度及滚动前后。区分宣传封面、手机模型包装、设计概念和已实现界面。
4. 涉及交互或动画，正式推荐前完整观看所采用的原片或实际操作完整相关流程，再逐帧分析所借用的动作。候选缩略图、描述和少量静帧不能证明已经理解动画。
5. 无法播放、需要登录或只能看到单屏时，清楚标记范围；继续寻找可核查替代。不要把作者文字里提到的其他页面说成亲眼看过。

## 读懂页面的空间性，再决定如何适配

- 不只读取平面布局和色彩。辨认用户提供的页面、现有产品及线上参考中可见的前后景、透视、体积、遮挡、光影和材质；动态时进一步看视差、运动轴、惯性、层级换位，以及物件和内容的连续关系。
- 找出案例成立的核心机制。空间轮播可能依靠Z位移、转角、尺度与遮挡共同变化；只留下横移或平面折叠会丢掉原作的重点。适配时说明保留、改变或舍弃什么，以及理由。
- 区分真正体积变化、三维空间中的平面和纯二维视觉暗示。不把平面光晕、同心波纹或整体旋转冒充不规则三维云体；不能仅凭静帧断言实现方式。技术选择服从观察到的效果，不因“三维”一词强行上WebGL。
- 空间性是一项观察和判断维度，不是所有页面都必须3D的风格规定。结合任务、可读性、触控和实现成本决定空间表达的强弱；稳定文字与表单可以保持平面。
- 主动检查本次范围内的整条交互：按下、拖动/选择、松手、进入、落位、返回及必要的打断。不等用户逐一指出缺少按钮反馈或页面跳转；各动作应与已选择的空间关系一致，而非只让主视觉持续运动。
- 页面个性来自有依据的构图和物件关系，不能停留在普通文本与等权卡片堆叠。先用代表页和完整动作检验方向；已被用户认可的布局或局部应保留并有针对性地优化。

## 动效分析要解释连续的动作

把原片按动作含义分组，例如触发响应 → 主体变化 → 背景退让 → 内容进入 → 稳定落位；按实际发生的过程命名，不硬套阶段。

每段说明：

- 时间范围、帧号及关键帧；什么保持连续，什么发生变化。
- 主体/背景/遮罩/文字/图标各自在何时移动、缩放、裁切、显隐、变形或改变材质；阶段怎样重叠和衔接。
- 动作的用途及其与触发操作的关系；返回、打断等仅分析实际看到的行为。
- 哪个动作直接借鉴、哪个需要改造、哪个舍弃，及适配当前布局的理由。

用户要求追帧图组时，按动作把图组实际展示出来并逐段讲解。要求全量逐帧时覆盖全部原始帧，提供读取顺序与帧号；采样总览必须标记采样率，不能冒充完整逐帧。避免仅堆图、只解释单张图，或把多支视频混成一个来源。

分开记录“画面观察”“作者说明”“设计推断”。没有可见手指/光标时不编造触发方式；宣传循环收尾不自动等于业务完成。没有测量时不报精确缓动曲线、原生帧率、触觉或响应性能。

## 先解释选择，再制作草稿

先把可核查的案例放到用户面前。每个建议至少回答：

- 艺术风格及具体构图/动作特点是什么？优势解决了什么问题？
- 适用什么场景，我们当前页面哪里匹配、哪里冲突？
- 推荐它的理由是什么，有什么代价或证据限制？
- 原地址在哪里？它是主参考、辅助参考还是未采用候选？

多个来源参与一个方案时，明确每个来源贡献的部分。可提供互有差异的方向并明确推荐；不只给“高级、精致、有趣”等形容词。

保持“看现状 → 学参考 → 讲清楚 → 做草稿”的顺序。当前请求已批准某方向时，直接接着制作，不重复研究或再设批准关卡。用户要求同轮完成研究和草稿时，在同轮依序交付；技能本身不新增权限流程。

## 让参考实际约束成稿

- 画稿前确定主参考，提取实际可见的构图、图像比例、对齐、字级、信息密度、边界/圆角、容器、材质及空间动作规则。不能只摘取“大图”“高级感”等局部印象，再套熟悉的组件模板；未测量的数值不编造成原作参数。
- 建立简短对应：**参考里的可见规则 → 草稿中的对应处理 → 保留或适配的具体理由**。主参考使用直角图片和弱容器时，先保留这套边界语言，不默认加圆角照片、卡片底、胶囊、阴影或承载块。新增处理须有参考证据或当前任务的明确需要，不能用“更像App”“更精致”代替理由。
- 需要适配时说明具体冲突与取舍。项目已有的按钮圆角要求只适用于它约束的控件，不能扩张成所有图片、分组和内容块的统一圆角；保留必要业务能力也不意味着可以随意改写参考的主要视觉语法。
- 交付前把参考与实际草稿并置复核，逐项核对上述规则以及采用的动作阶段。发现稿件又回到惯性卡片模板，应先修正，再展示；不能只解释参考的优点，却忽略成稿的明显偏离。
- 严格参考不等于统一禁用某种形式。圆角、直角和复杂程度都由该次证据与适配需要决定。没有说明依据的形式选择不进入实现，也不能把自行增加的处理说成来自参考。

## 以简练为基础进行设计判断

- 从必要结构和清楚的主次开始。复杂参考可以转化为合理的复杂设计；简练不等于以后所有页面固定极简。
- 每个元素应有明确理由：使用、识别、层级、构图、品牌或气氛均可。先判断是否成立，再决定保留。
- 警惕习惯性英文小标题、章节编号、重复标题、同义说明、无任务意义的装饰和满页等权卡片。参考站出现这些元素，也不代表产品里需要。
- 用比例、对齐、留白、字级、色彩面积、边界与前后景建立设计感。提高复杂度时集中在必要的主视觉或动作关系上。
- 学参考的组织原则与动作关系，结合产品重新设计；不把“换颜色、套玻璃、放大字”当作完整的风格适配。
- 不为更好看而添加未确认的会员、排名、里程、等级、AI、实时追踪等业务能力。样例内容需在草稿说明中标记，不伪装真实数据。

## 草稿与验证

- 优先用 HTML/CSS、SVG 或 Canvas 制作可直接看的草稿；需要位图素材时再选合适工具。研究图、原片和自己的稿件应清楚区分。
- 多页面先做少量有代表性的页面，检验同一视觉语言下的构图差异，再扩展全量。保留当前页面入口与已有内容；信息密集页面可降低材质和装饰强度。
- 对照参考复核字号比例、间距、边缘、裁切、阴影、时序、动作层次和落位，不能只证明“功能跑通”。动画顺滑需要观察完整播放及衔接，不能仅凭相邻像素相似度下结论。
- 实际在浏览器或目标预览中查看，检查关键尺寸、图片加载、文字可读、遮挡、安全区、滚动及本次承诺的交互。修正发现的问题后再保存可核查截图或视频。动效任务提供可操作入口及能看到完整动作的记录，静态截图只作补充；截图采样导出需标明采样率与慢放设置。
- 交付可用链接/文件、直接显示的预览、适配说明，以及实际实现和验证边界。不要把草稿写成已落地 App、真机验收或新的全局规范。
- 使用当前项目的工程与授权规则；独立研究稿不自动扩为业务改造、部署、提交或推送。用最小必要验证，不为纯视觉探索另起无关工程流程。

需要对照常见偏差与适配判断时，再读 [设计判断示例](references/design-decisions.md)。示例用于说明方法，不能替代当前页面证据。
